6. Rulings needed: none. Readings, each ruled from the documents' purpose and listed in the PR body: (a) Who is walled. The `developer` stands behind `wall.functional`; `qa` stands behind `wall.unit` and `wall.code`, with the files `wall.interface` lists open to it whole. The two verifiers, `receipts` and the Orchestrator are not walled: the QA verifier writes its mutations on the code at two-key. (b) Which calls are checked. Read, Edit, Write and NotebookEdit by their file; Grep by its `path` and `glob` (its `pattern` is a regex, not a path); Glob by its `path` and `pattern`; Bash by each word of its command. Other tools pass. A path resolves against the repository root; a path outside it passes. A write crosses as a read does (the Developer writes no functional test, ADR 0010). (c) What crosses. A wall entry ending in `/` is a folder; any other entry is a glob. A path crosses when it sits in a walled folder or matches a walled glob; a word that is itself a glob (`tests/*`) crosses by the same test. For QA, a code path that matches `wall.interface` passes. (d) The one Bash call that names a code path QA may make is `python -m taskcontract interface FILE`: it passes the code wall, never the unit wall. (e) A refusal exits 2 with the design's line on stderr (`Task {task}: {Operator} reads no functional test: {path}`, and QA's two), naming the operator as `task.py` prints it and the first path that crosses. (f) The hook refuses nothing, exit 0, when no task file stands or it cannot be read, when its operator is not walled, when the repository has no `wall:` block or is no git repository, or when the hook's own input cannot be read. While no task runs it reads nothing past the task file, so it costs a consumer no import. (g) `taskcontract/declaration.py` gains `read_wall(root)`: the four lists, an absent key read as empty, or None with no `wall:` block. (h) `interface` prints, in file order, each public top-level function and class: decorators, the `def` or `class` line, and the docstring's first line, with ` ...` when more follows (the design's drawn output). A class adds, indented, its annotated fields and its public methods, `__init__` among them. It reads the file on disk; at a task the checkout is the commit. The checks run in the design's order: not `.py`, then missing, then unparseable, each exit 2. (i) `hooks.json` gains one PreToolUse entry for the seven tools, running `python "${CLAUDE_PLUGIN_ROOT}/hooks/wall.py"`. (j) No retirement: no test pins what e3 changes (`test_session_size.py` finds its two hook entries by command, so a new entry leaves it green). (k) One session, split at the test list only if the session's context passes about 200K tokens (CONTRIBUTING's target); the handoff then goes in the receipt folder.
7. What could go wrong, already ruled. This session runs no task file and does not load the kit as a plugin (the installed copy predates `hooks/`), so the wall it builds never walls its own build. The tests feed `wall.py` hook input on stdin in a `tmp_path` git repository with its own `wall:` block and a task file written as the design draws it, never the kit's. A Grep or a script over the repository root can still read a walled file without naming it (design Risks 6): the hook matches what a call names, as signed. A Windows path's drive letter and separators: the hook compares paths relative to the root with forward slashes. Two whole suites never run at once. Two-Key fails a round: one narrow fix round, tests first; after a third failure Claude stops.

10. Words. Wall: the line between the Developer and QA that `.sdlc/config.yaml`'s `wall:` block draws: `functional` (QA's tests), `unit` (the Developer's tests), `code` (the implementation), `interface` (the code files QA reads whole). Task file: `.git/sdlc-task.json`, never committed, naming the running task, its operator and its round. Operator: the team member a task step belongs to. Implementation body: the code inside a function, which QA never reads. Interface: a file's public signatures and docstrings without bodies. PreToolUse hook: a command Claude Code runs before each tool call; its exit 2 refuses the call. Probe: a throwaway run that measures one fact before the build leans on it. Drafter, developer, Two-Key: the build's three agents (tests first, then code, then an independent grade). Prove-red: the record that the new tests fail before the code exists.
