6. Rulings needed: none. Readings, each ruled from the documents' purpose and listed in the PR body: (a) "Moved" means copied into the tracked tree; the untracked copies stay until e4 retires them (the design's Units row for e4), since this build's own drafter and Two-Key still run them. (b) `prove.py` runs from the repository root, as today, and reads the declaration there with `read_test`, importing the `taskcontract` beside it as `task.py` does. With no `test.command` it exits 2 with `prove.py: the repository declares no test command`. `--timeout SECONDS` stays (default 600). (c) Each run exports REV afresh into `DIR/export/` (`git archive`, then Python's `tarfile`), so a mutation a killed run left cannot survive; the journal and `recovered`, which guarded the prototype across runs, retire with it. A REV that is not a commit, or a root that is no git repository, exits 2. (d) The draft sits at `DIR/draft/PATH`, PATH from the repo root; prove.py copies it to `export/PATH`. With no draft there, the export's own file at PATH runs (a committed test, at two-key); with neither, exit 2. (e) Without `--mutations`, prove.py proves red only: `test.build` (when declared), then `test.file` with `{file}` as PATH, or `test.command` when no `file` is declared, from the export's root. A build that exits non-zero gives `red_ok: false`, its summary naming the build. (f) With `--mutations`, it proves the mutations only, as the design's two-key JSON draws (no `red` key): first the unmutated run, which must pass, else `"mutations": "skipped: the tests do not pass at REV"` and exit 1; then each mutation applied to the export, run, and restored byte for byte. `file` is relative to the export's root. (g) A pytest command is one whose argv holds `pytest` or whose `argv[0]` stem is `pytest` (`receipts.py`'s test). Only then prove.py appends `--tb=short`, `--junitxml=DIR/logs/{run}.xml` and `-p no:cacheprovider`, and reads results per test (`red_ok`: every test fails on an assertion; `caught_by`: failing ids). For any other command, `red_ok` means exit 1, `summary` is the last non-empty output line, and a mutation is caught when the run exits non-zero, `caught_by` listing PATH. A command whose `argv[0]` cannot start exits 254. (h) In both scripts an `argv[0]` naming a file in the repository (the export, for prove.py) resolves there before `PATH`. (i) The batch-file fixture is `test.bat` on Windows and an executable `test.sh` elsewhere, since CI runs on Ubuntu; the tests pick by `os.name`. (j) "pytest only where it is declared" is pinned by a batch-file fixture whose repository also holds a `test_*.py` that writes a marker when pytest collects it: the marker never appears. (k) One session, split at the test list only if the session's context passes about 200K tokens (CONTRIBUTING's target); the handoff then goes in the receipt folder.

10. Words. Declaration: the `test:` and `wall:` blocks of `.sdlc/config.yaml`. Test command: `test.command`, the argv the team runs for the whole suite; `test.file` runs one test file, `test.build` runs first. Export: the tracked tree at one commit, unpacked into the scratch folder. Draft: a test file not yet committed. Prototype: the drafter's scratch copy of the files a unit changes, used only to prove the tests can pass; QA in the team writes none. Mutation: a one-place change to the code that a test must catch. Retirement: removing a test that pins code the unit deletes. Two-Key: the grade of a unit by an agent that re-runs its receipts independently.
