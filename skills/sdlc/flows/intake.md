<purpose>
The Intake flow of the `/sdlc` skill, the G0 venue: raw request in,
ready contract out. G0.1 reads `enforced` for a repo once this flow is
how tasks enter development. Dispatched by {skill-dir}/SKILL.md on
`/sdlc intake`; its constraints and criteria bind here. {skill-dir} is
the directory holding SKILL.md.
</purpose>

<instructions>
I1. CHECK the seat roster first - one Bash call: `python -m taskcontract vocab-list`. When the `intake-seat` row is absent or not `ratified`, STOP before any contract exists: REPORT this line verbatim, write nothing, and return to the conversation: "No ratified seat roster. Author and ratify specs/vocabulary/intake-seat.yaml (`/sdlc vocab add intake-seat` drafts it), then run intake again." Otherwise COLLECT the raw request - the invocation text after `intake`, or ask the user for it.

I2. DERIVE a task id matching `^[a-z][a-z0-9-]{2,63}$` from the request; if the derivation is unclear, confirm it with the user (AskUserQuestion). When the request is a feature document at `docs/features/{id}.md`, READ it here, before the scaffold, in four parts, in this order. A pair that stops or parks here gets no contract: nothing under `specs/` is created or changed.
    DESIGN - it is the requirements document of a pair: FIND the design document beside it, at `docs/features/{id}.design.md`. With none, STOP: REPORT `No design document for {id}. Run the design interview first.`, write nothing, and return to the conversation.
    REFUSALS - read on both documents. Intake refuses ready while any of these stands:
    1. An OPEN mark in either document.
    2. A ready check with a gap. READ the requirements document against ready checks 1 to 8 and the design document against 11 to 15, each a question: asked, never parsed (ADRs 0029, 0033 and 0037; `{skill-dir}/../product-specification-interview/flows/signing.md` holds the questions at P3 and E3). A gap reads `Ready check {n}: {gap}. Marked OPEN.` A gap that already carries its OPEN mark counts once, as that mark.
    3. A check of the requirements document assigned to no unit, or to two, of the design document's Units, or a unit that delivers no check. A check's unit is read from the Checks cell of its row under Units, where `+` joins two checks that share one sketch entry. Each message names its id, verbatim: `Check {id} is assigned to no unit.`, `Check {id} is assigned to units {a} and {b}.`, `Unit {id} delivers no check.`
    PARK - a refusal parks the pair. Intake reads the refusals on the pair as it stands: a pair with something standing parks even when a signature is missing or the design is stale. WRITE one row into each document's revision table: the date, `intake` in the Revised By cell, and the changes cell `r{n}: Parked: {what stands}`, with r{n} one past that table's last row. Both rows hold the same list. `{what stands}` names every thing that stands, each in its own words, one after another on one line, the requirements document's things first, then the design document's, each in this order: the OPEN marks in document order, then the ready-check gaps by check number, then the Units messages, by check and then by unit, in the document's order. Intake writes nothing else: it changes no section and writes no contract. REPORT the same list and return to the conversation; each seat fixes its document through its own run, signs again, and intake runs again. A `Parked:` row changes no text: a later run reads the pair afresh, and an earlier `Parked:` row parks nothing. Intake writes `Ready:` and `Parked:` rows, and never a `Signed:` row.
    STOPS - read only when nothing stands. A document's newest text revision is the highest row of its own table that opens on none of `Ready:`, `Measured:`, `Signed:` or `Parked:`. Its signature is its table's latest `Signed:` row: the signer is that row's Revised By cell, and the revision it signs is the newest text revision above it, never the `Signed:` row's own number (ADR 0034). The design names the `requirements r{m}` of its table's newest text row that names one. A design is stale when the requirements document holds a text revision newer than the one the design names. REPORT each case that holds, verbatim, in this order: `The requirements document has no PO signature on r{n}.` and `The design document has no engineer signature on r{n}.`, each when that document's signature signs an older revision than r{n}, its newest text revision, or none; then `The design names requirements r{n}; the requirements stand at r{m}. Stale.`, with r{m} the requirements document's newest text revision. When a case holds, STOP before any contract exists: write no row and no contract, and return to the conversation. A stop gets no `Parked:` row: the three refusals are all that parks a pair. The seat signs, or confirms the design, through its own run, then intake runs again.

I3. SCAFFOLD - one Bash call: `python -m taskcontract new {id}`. If it fails because the contract already exists, ASK before touching anything - existing contracts are never silently edited.

I4. AUTHOR `specs/{id}/contract.yaml` from the request: intent in outcome terms (40-1200 chars - what is true after this task that is not true now); scope paths; non_goals; decomposition units each with a unique `id`, done_means and 1-3 acceptance_sketch criteria, plus `depends_on` where order matters; dependencies as {ref, status: resolved or blocked, blocked_by}; provenance origin `human-request` unless the task demonstrably originates from an operations escape (`g8-escape`, requires ref) or maintenance (`g9-maintenance`). For a pair, each contract field has one source: the title, the statement, the non-goals, the checks and the terms from the requirements document; the scope, the units, each `done_means` word for word, the order and the tests from the design document. When the request is a feature document, WRITE `title:` from its title line `# {id} - {title}`: the words after `{id} - `, or the whole heading text when the heading opens on anything else. COPY each unit's `done_means` word for word from its row's Done means cell under Units: the document wins over any wording intake would derive. Intake never rewords a copied `done_means`, at I5 or at I7: a change the seat names at I5, or a diagnostic at I7 that names a `done_means`, goes to the document's Units row through the interview and a new signature, and intake runs again. WRITE each check into the `acceptance_sketch` of the unit its Checks cell names, the check's id last in its entry, inside `( )`. A unit holds at most three entries: a unit of more than three checks pairs two in one entry that ends in both ids, the two its Checks cell joins with `+`. The two ids stand inside one `( )` at the end of the entry with a comma between, as `(SC2.2, SC2.3)`; the tree reads that pair as the check `SC2.2+SC2.3`. The `+` belongs to the Units table's Checks cell and to the tree's id, never to the sketch entry. The three plan answers are the engineer seat's, asked in these words when the request does not carry them: which files change (`scope`), in what order (`depends_on`), which tests prove it (`acceptance_sketch`). When the request is a feature document, READ the three from its own sections (files from Scope, order from Order, tests from the Tests cell of each row under Units) and note each as taken from the document, for the I5 readback only, never as a contract field. Check `vocab-list` and ALWAYS declare `entities:` - the ratified terms the request's nouns match. When nothing matches, propose `entities: []` for the I5 readback; never write the empty list by default.

I5. RENDER + CONFIRM - one Bash call: `python -m taskcontract graph specs/{id}/contract.yaml`. SHOW the Mermaid and every unit's `done_means` inline. Every unit needs a human answer before the contract is final: ASK per unit (AskUserQuestion, up to four units per call) - keep, change (the answer names the change), or strike. SHOW the three plan answers (files as `scope`, order as `depends_on`, tests as `acceptance_sketch`) beside their source (the document's Scope, Order and Units sections, or the seat's own words) and ASK the engineer seat to keep or change them; never ask afresh what the document already answers. ASK which seats answered for each unit, or take them from the invocation when it names them; a seat is one of the `intake-seat` term's own values. When the proposal is `entities: []`, ASK the PO seat to confirm that the contract operates on no glossary term, or to name the terms it does.

I6. WRITE the confirmed contract: apply every change and strike, add `confirmed_by: [seats]` to every unit from the answers, and write `entities: []` only when the PO seat confirmed it at I5, else the terms the seat named. This write is the contract; nothing before it is final.

I7. LOOP - one Bash call per iteration:
       python -m taskcontract validate specs/{id}/contract.yaml --profile ready
    Fix exactly what each TCnnn diagnostic names. A TC010/TC011 means the vocabulary lacks the term: fork it (`/sdlc vocab add {slug}`, own small task) or drop the ref - NEVER ratify a term just to turn a contract green. A drop that leaves `entities` empty returns to I5: the PO seat confirms `[]` or names the terms, as for any empty list. A TC016 means a unit went unanswered or an answer named a seat the term lacks: return to I5 for that unit. Cap at 5 iterations; if still red, REPORT the remaining violations and return to the conversation. When the loop ends ready-green and the request is a feature document at `docs/features/{id}.md`, ADD one row to each document's revision table: the date, `intake`, and a changes cell that opens ``r{n}: Ready: contract `{id}` validates ready-green, derived from r{m}``, with r{n} one past that table's last row and r{m} that table's signed text revision, as I2 read it. Each cell then names its own seat and the revision that seat signed. The requirements document's cell goes on ``; the PO seat ({name}) signed the request half at r{m} (r{b})``. The design document's goes on ``, against requirements r{k}; the engineer seat ({name}) signed the solution half at r{m} (r{b})``. r{b} is the `Signed:` row's own number, {name} that row's Revised By cell, and r{k} the requirements revision the design names.

I8. PARKED CASE - if a dependency is blocked in fact: set {status: blocked, blocked_by}, VERIFY `--profile draft` passes, then REPORT the contract as PARKED with the named blocker and REFUSE the development handoff - `ready` is the entry gate. A feature document gets no `Parked:` row here: a parked document has no contract, and this contract stands at draft.

I9. REPORT the contract path, its state (ready-green, or parked-draft + blocker), the seats recorded, and a one-line scope summary. Development starts only from green.
</instructions>
