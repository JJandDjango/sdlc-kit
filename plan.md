Project  SDLC kit: gates that stop agent-written code from degrading a codebase.
Area     The kit's own flow: how a session in this repo is sized, started and closed.
Feature  small-session-flow (Workflow Nodes): each stage of the flow runs as a node at its own agent model and effort, and each session ships one deliverable inside 400K tokens.
Unit     `w1-session-size` (the first of four units, not started). Session 112.

1. The deliverable. By this session's end `w1-session-size` is built on the branch `session-112-w1-session-size`, graded PASS by Two-Key, and its PR is open for the user's review. Done means, from the contract: "`CONTRIBUTING.md` states the one deliverable, the 200K target and the 400K limit. The plugin hook shows each message verbatim once a session when the context passes its threshold."
2. Where this sits. The contract `specs/small-session-flow/contract.yaml` is on main since PR #132 (`a985f7a`). Its design orders the units w1, w4, w2, w3, one a session. w1 adds the kit's first plugin hook (a script Claude Code runs on an event, shipped with the kit's plugin): `hooks/hooks.json` and `hooks/context_size.py`. Past 200K tokens of context it shows `This session has passed 200K tokens, the target. Finish the deliverable and close.`; past 400K, `This session has passed 400K tokens, the limit. Save the notes and close now.` The design's constraint 8 keeps the hook silent in a repo with no `.sdlc/workflow.md`, a file w2 writes later, so in this repo the hook stays silent until w2 lands. This build is also the first real use of `prove.py` and `receipts.py` (backlog Next 8).
3. The steps (nine). (1) Claude opens the branch and pushes this plan. (2) Claude measures, with no agent, and saves the results in the receipt folder `RECEIPT_small-session-flow-w1_2026-10-22/`: the fields a hook gets on stdin and the usage fields of an assistant line in a real transcript on this machine, read by a scratch probe; the hook file format of an installed plugin; and the time to read a 50 MB transcript backward (constraint 2 caps it at 500 ms). (3) The drafter, an agent that writes the tests and never the code, writes the test list through `spec-channel-drafter.js` and proves it with `prove.py` (the script that runs the list red on the repo, green on a prototype, and against mutations). (4) Claude checks the list: the whole suite on the prototype in a scratch worktree, each fixed detail against the contract, the design's Constraints and Sources, and the ratified terms, and five hostile transcripts (empty, truncated last line, no assistant line, a subagent line, non-UTF-8 bytes); then records `approve-tests --by claude` and places the tests red. (5) The developer, an agent that writes code from the drafter's interface note and never reads the tests, writes the hook through `unit-developer.js`; Claude types the two `CONTRIBUTING.md` lines the design gives word for word, and drafts the ADR the design asks for (the plugin hook and the `node` command). (6) Claude runs the whole suite, commits the unit, and records each check with `progress run`. (7) The manual receipt: a headless session started with `--plugin-dir` on a worktree at the unit's commit, in a scratch repo that holds a stand-in `.sdlc/workflow.md`, pushed past 200K by a large prompt file; the receipt is the hook's message as that session's transcript records it. (8) Two-Key, an agent that grades the unit from its own reading, gets `receipts.py`'s JSON as `receiptsResult`, so no receipts agent runs. (9) Claude's last commits remove `plan.md`, tick backlog Next 8, add the row to `docs/session-metrics.md`, turn the 🟡 marks on `prove-py.md` and `receipts-py.md` 🟢, and delete the receipts agent's path in the untracked `two-key-unit-verifier.js`; Claude opens the PR after green CI and a PASS.
4. Where Claude stops for the user. The PR review and its merge. The ADR goes to the user inside the PR, named first in its body, and the review approves it or sends it back. A stop at any step if the work would change a signed sentence, a ratified term or an existing ADR.
5. Where Claude goes on alone, and by what rule. Steps 1 to 9: the measures, the test list (recorded `--by claude`), the commits, the receipt. The rule (`CONTRIBUTING.md:17`): the signed documents are the gate; a reading they leave open is ruled from their purpose and listed at the top of the PR body.
6. Rulings needed: none. Readings: (a) `prove.py` copies only the `taskcontract` package, so the drafted test finds the repo through `taskcontract`'s location, and the prototype holds `hooks/` and the two pages beside its copy of the package; green then reads the prototype, and the suite, run against an editable install, reads the repo. (b) The hook runs on `PostToolUse` and `UserPromptSubmit`: the first reaches a long run of tool calls, the second a turn with none. It shows the user its message as `systemMessage` and gives the agent the same text as `additionalContext`. (c) One marker file a threshold a session id, in the temp directory; a step past 400K writes both markers, so the 200K message never follows the 400K one. (d) The hook is started as `python`, as the kit's other commands are. (e) One session, not session 96's two: the design says one unit a session, and the unit is small. If the context passes 200K when the list is recorded, Claude splits there with a handoff file in the receipt folder.
7. What could go wrong, already ruled. The transcript format is not a public contract (design risk 1): the fixture tests pin the fields read, and step 7 checks them live. A plugin hook runs in every repo with the kit's plugin enabled (risk 2): a test pins silence where `.sdlc/workflow.md` is absent. A new top-level `hooks/` folder may draw a Cairn audit finding: `ARCHITECTURE.md`'s folder map gains its row in step 9. Two-Key fails a round: one narrow fix round, tests first; after a third failure Claude stops.

9. Not in this session. The units w4, w2 and w3, one a session after this one. Moving this machine's installed plugin off `8635064`, which the hook needs to reach a normal session here. The G1 readings of PRs #116 and #119 and the other backlog Open questions. Each stays on the backlog.
10. Words. Hook: a command Claude Code runs on an event, here after each tool call and each user message. Plugin hook: one the kit's plugin ships, so it runs in each repo where the plugin is enabled. Transcript: the session's log file, one JSON line per message, whose path the hook gets. Context: the tokens a request sends, read from the newest assistant line's input, cache-write and cache-read counts, summed. Marker: a temp file that records a message as shown for one session. Prototype: the drafter's scratch copy of the files the unit changes, used only to prove the tests can pass. Manual receipt: evidence taken by hand from a live run, handed to Two-Key. ADR: an append-only decision record under `decisions/`.
