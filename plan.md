Project  SDLC kit: gates that stop agent-written code from degrading a codebase.
Area     The kit's own flow: how a session in this repo is sized, started and closed.
Feature  small-session-flow: each stage of the flow runs as a node at its own agent model and effort; this deliverable shortens the suite every stage waits on.
Unit     None: backlog Next 14, make the whole suite faster (the user's question, session 116). Session 119.

1. The deliverable. By this session's end the whole suite runs on parallel workers (`pytest-xdist`, `-n auto`) wherever it runs whole: CI, Two-Key's receipts and the agent briefs that run it. The before and after times on this machine are recorded on the branch `session-119-faster-suite`, and its PR is open for the user's review.
2. Where this sits. The suite is 2085 tests, run one at a time in about 460 s. It runs whole in four places: CI (`.github/workflows/ci.yml:17`, `pytest -q`); Two-Key's receipts, an argv list the session hands to `receipts.py`; the developer's brief (`unit-developer.js:40`); the retirer's brief (`test-retirer.js:66`). The last three sit in untracked `.claude/workflows/`. This machine has 16 logical CPUs, and GitHub's Linux runner has 4. The tests change directory only through `monkeypatch.chdir` into temporary folders, the session fixtures in `tests/conftest.py` only load modules, and no test writes under its repo-root constant, so workers share nothing they write.
3. The steps (five). (1) Claude pushes this plan. (2) Measure: the whole suite with `--durations=25` on the branch head, serial. (3) Trial: a scratch worktree and a scratch venv (the system packages plus `pytest-xdist` 3.8.0, with pytest pinned to the system's 9.0.2). The suite runs three times at `-n auto` and once at `-n 4` (a stand-in for CI's runner), and each run must match the serial count with no failures. (4) Adopt, if step 3 holds: `pyproject.toml`'s `test` extra gains `pytest-xdist`; `ci.yml` runs `pytest -q -n auto`; `pytest-xdist` goes into the system Python; the suite command in `receipts.py`'s usage text, `unit-developer.js`, `test-retirer.js` and `docs/conventions/standing-practice.md` gains `-n auto`; and `test_receipts.py` gains one case that reads an xdist run's summary. (5) The close: commit with `Contract: small-session-flow`, tick Next 14 with the measured times, `plan.md` out, a draft PR, ready after green CI.
4. Where Claude stops for the user. The PR review and its merge. A stop earlier comes only if step 3 fails in a way that needs a test's meaning changed.
5. Where Claude goes on alone, and by what rule. Steps 1 to 5. The rule (`CONTRIBUTING.md:18`): no approval before the final PR review. The backlog entry is the user's ask, and a reading it leaves open is ruled from its purpose (less time waiting on the suite) and listed at the top of the PR body.
6. Rulings needed: none. Readings: (a) `-n auto` goes in each whole-suite command, not in `addopts`. A one-file run (`prove.py`, a developer's single file) stays serial, since 16 workers take seconds to start, and `pytest` still runs where `pytest-xdist` is missing. (b) `receipts.py` runs the argv it is given and adds no flag, so the receipt shows the command that ran. Its parser needs no change: an xdist run prints the same last-line summary and the same `FAILED` lines (checked on a toy suite). (c) Installing `pytest-xdist` into the system Python follows from the ask, since the receipts run under it. `pip uninstall` reverses it, and the PR body names it. (d) No Two-Key round: no kit code changes. The check is step 3's runs and CI's whole suite on xdist. (e) No session-metrics row: no unit ships.
7. What could go wrong, already ruled. A test that depends on another's side effect or order passes serially and fails on a worker. If so, the test gets its own setup if that keeps its meaning; else it is a stop. A collection that differs between workers (a parametrize over an unordered set) makes xdist refuse the run: its ids get a fixed order. The slowest test sets the floor of a parallel run: step 2 names it, and speeding it up waits for its own backlog line. CI on 4 workers gains less than 16 locally: the `-n 4` run gives the estimate.
8. This session's cost, with its basis. No agent runs, so about 0 agent tokens. Suite runs: one serial (about 460 s) and four parallel (each a minute or two if the gain holds). The session's own context is the cost: about 70K at this plan, and the adoption edits are small, so the close should land near 120K.
9. Not in this session. Speeding up the slowest tests themselves. Parallel runs inside `prove.py` (it runs one file). A CHANGELOG entry: it waits for a release.
10. Words. Worker: one of the pytest processes xdist starts; each takes a share of the tests. `-n auto`: one worker per logical CPU. Serial: one test at a time in one process, the suite's run today. Receipt: a command whose exit code Two-Key reads as proof. Two-Key: the grade of a unit by an agent that re-runs its receipts on its own. Scratch worktree: a second checkout of the branch under the session's scratch folder, removed at the close.
